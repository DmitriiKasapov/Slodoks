# Карта URL старого сайта

`old-site-urls.csv` — структура действующего сайта https://slodocs.si/ на
Laravel. При переносе на WordPress эти адреса должны сохраниться символ
в символ либо получить 301-редирект.

## Статус: НЕПОЛНАЯ

Есть только статические маршруты. **Страниц услуг в файле нет** — а это
основная часть сайта.

## Как получена

Обход сайта невозможен: `robots.txt` блокирует ClaudeBot, сервер отдаёт 403.
Данные сняты из исходников проекта `D:\Projects\SloDoks`:

- статические маршруты — `routes/web.php`;
- состав `sitemap.xml` — `app/Http/Controllers/SitemapController.php`.

Дата снятия: 02.08.2026.

## Чего не хватает

**1. Слаги страниц услуг.** Маршрут `/services/{slug}` динамический, реальные
адреса лежат в базе. Файл `pgexport/data_export.json` в проекте SloDoks для
этого **не подходит** — там данные другого сайта (Jezicek), который работал
на том же приложении. Нужна выгрузка из боевой базы именно slodocs.si:
поля `slug`, `title`, `seo_title`, `seo_description`, `is_active`.

**2. Выгрузка Google Search Console** (Индексирование → Страницы). Показывает,
что Google реально проиндексировал и какие адреса приносят трафик. Только она
найдёт старые URL, которых уже нет в коде, но которые живут в индексе.
Класть рядом как `gsc-export.csv`.

## Колонки

| Колонка | Значение |
|---|---|
| `url` | Путь без домена |
| `type` | static / service / redirect / protected |
| `title` | Заголовок страницы |
| `seo_title`, `seo_description` | Мета-теги, если заданы в базе |
| `in_sitemap` | Входит ли в `sitemap.xml` |
| `indexable` | Должна ли страница быть в индексе |
| `source` | Откуда взята строка |
| `notes` | Примечания |

## Что уже известно о структуре

- В `sitemap.xml` попадают: `/`, `/catalog`, `/contact`, все активные
  `/services/{slug}`, `/terms`, `/privacy`.
- `/search` — редирект на `/catalog` с сохранением `?q=`.
- `/services/{slug}/content` закрыт токеном и запрещён в `robots.txt`.
- `/admin`, `/payment`, `/webhooks` запрещены в `robots.txt`.
